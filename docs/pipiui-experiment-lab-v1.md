# PipiUI 实验台扩展规格 v1

- 状态：待用户批准；本轮只交付规格与分票，不授权业务实现、安装依赖、运行付费实验、打包或重启。
- 日期：2026-09-20。
- 扩展身份：`experiment-lab`，显示名「实验台」，可选的 coding 扩展。
- 实施计划：`pipiui-experiment-lab-v1`。文末切片定义交付边界，实际任务状态以该计划为准。
- 来源：用户要求面向 PipiUI coding 及其他 Pi 项目，按需制作一个或多个原型，在隔离环境对比测试，获得数值证据后由用户决定是否采用；并非所有开发任务强制实验。

## 问题陈述

当前讨论设计或优化时，文字推理、一个可点击原型、一次测试通过，都不足以证明某个方案值得实施。用户需要看到候选方案与当前实现的公平对比：质量是否提高、完整任务是否更快、成本是否增加、失败是否更多，以及结论还存在哪些局限。

现有 `prototype` skill 可以制作界面或逻辑原型；PipiUI 已有浏览器、Worker、独立工作树与用量记录；个别扩展已有专用评测脚本。但这些尚未组成通用的实验对象、冻结基线、受控执行、可重放报告及用户采纳流程。普通 Worker 成功后的自动合并尤其不符合一次性实验的要求。

目标不是为全部任务增加审批仪式，也不是建设通用云评测平台，而是让用户能以较小、明确的预算回答一个设计或优化问题，再决定是否进入正式实现。

## 解决方案

增加项目范围的可选「实验台」。用户可以自然语言发起实验，也可从扩展入口打开实验面板。

一次完整体验：

1. 说明要验证的问题，例如「宽召回是否提高任务成功率，代价是多少」。
2. 从当前项目形成可追溯基线，登记现状与少量候选方案、测例、指标、限制和预算。
3. 按需生成隔离的代码原型，或登记仅改变模型、提示词、工具及扩展开关的配置方案。
4. 在同一批测例和声明的环境中执行，保存成功、失败、超时及取消的证据。
5. 展示各方案和基线的差异、波动、失败案例及未证明事项，允许复跑或查看原型。
6. 用户选择采用、继续试验或放弃。采用产生正式实现交接，不自动合并原型，也不替用户断言方案已经适合生产。

首版支持三种实验，通过同一记录和报告契约连接：

| 类型 | 最小产物 | 验证方式 |
| --- | --- | --- |
| 命令／逻辑／性能实验 | 冻结的代码、输入与项目测试或 benchmark 命令 | 确定性验证器、退出状态、机器计时、项目自定义数值指标 |
| Pi 行为实验 | 基于相同任务的 agent profile 与可选代码变体 | 真实目标 Pi 进程、固定任务判定、调用轨迹与可用 usage |
| 界面原型实验 | 可交互页面及可选择的方案 | 内置浏览器操作、双视口检查、截图及用户评价 |

界面实验中的审美意见不自动伪装成客观分数；不是每个实验都必须同时具备上述三种类型。

## 用户故事

1. 作为开发者，我希望在有设计不确定性时才进入实验，以便小修复仍可直接完成。
2. 作为开发者，我希望用自然语言说明比较目标，以便不用先学习 benchmark 命令。
3. 作为用户，我希望看到当前实现作为基线，以便知道候选方案是否真的改善了现状。
4. 作为用户，我希望只比较两个或少量有区别的方案，以便不会为无意义的变体付费。
5. 作为用户，我希望已有未提交代码不会丢失，且知道它是否进入实验基线，以便实验对应我正在讨论的版本。
6. 作为开发者，我希望冻结相同输入、测例和评分规则，以便方案之间可比较。
7. 作为用户，我希望先生成可操作的逻辑或界面原型，以便验证仅靠描述难以判断的设计。
8. 作为用户，我希望能够自行打开预览、切换方案和反馈，以便保留主观设计判断。
9. 作为开发者，我希望原型生成完成也不会自动进入正式代码，以便试验不会改变生产方向。
10. 作为开发者，我希望比较不同 Pi 工具、扩展、提示词或模型配置，以便优化真实 agent 行为。
11. 作为评测者，我希望确认测试使用的是目标 Pi runtime，而不是系统中另一个同名可执行程序，以便结果对应实际产品。
12. 作为用户，我希望看到完整任务耗时和分阶段耗时，以便不把局部加速误认为整体加速。
13. 作为用户，我希望看到质量、成本和稳定性的取舍，以便不被单一综合分代替决策。
14. 作为用户，我希望费用缺失时显示未知、估算时明确标记，以便报告不会把估计当账单。
15. 作为评测者，我希望所有失败、超时、回退和无效运行都可见，以便报告不筛掉不利结果。
16. 作为评测者，我希望对有随机性的测例重复运行并看到波动，以便不凭一次好运选方案。
17. 作为用户，我希望运行前知道最大轮数、时间和可能的网络／模型调用，以便控制投入。
18. 作为用户，我希望随时停止实验并保留已获得的证据，以便取消不意味着丢失全部工作。
19. 作为用户，我希望项目切换、会话退出或异常中断后仍能查看结果，以便报告不依赖聊天上下文。
20. 作为用户，我希望关闭扩展后不再启动新实验，也不改变普通开发路径，以便该能力真正可选。
21. 作为用户，我希望试验进程不能写正式工作区或读取未授权凭据，以便原型的副作用受控。
22. 作为用户，我希望本地实验不要求云账号，以便可以使用私有代码完成基础验证。
23. 作为用户，我希望每个 Pi 项目拥有自己的测例与实验历史，以便配置和数据不会串项目。
24. 作为用户，我希望报告可以追溯到日志、截图和具体代码版本，以便复核 AI 的结论。
25. 作为用户，我希望查看失败样例并发起新的修订轮次，以便迭代不覆盖旧证据。
26. 作为用户，我希望由自己选择采用方案，以便自动评分不能越过产品决策。
27. 作为开发者，我希望采用后获得准确的实现交接，以便可以复用已验证逻辑，但不会把 mock 和试验 UI 整体搬进产品。
28. 作为用户，我希望在样本不足或环境不一致时看到「证据不足」，以便不会被虚假的胜出结论误导。
29. 作为维护者，我希望无模型凭据也能验证实验台功能，以便 CI 不依赖付费服务。
30. 作为用户，我希望错误能关闭、运行有进度、清理有明确对象，以便实验失败不会阻塞后续聊天。

## 实现决策

### D1. 可选扩展与首版范围

- 使用现有扩展发现、启停、设置、工具结果渲染和 Workbench 贡献机制，不加入基础必需扩展集合，不要求所有 Pi 产品默认启用。
- 扩展拥有实验领域模型、测例契约、比较报告和用户采纳；不替换 Pi runtime，不新建第二套通用调度系统。
- 复用现有 Worker、Git 工作区管理、浏览器与进程生命周期基础设施；需要的新增能力明确作为实验专用适配器实施，不宣称目前已有公开 `HostJob` API。
- 首版以本地 Git 项目为基线来源，macOS 为真实验收平台，Linux 复用已支持的本地执行路径并分别记录验证状态；未支持的平台清楚提示，不静默无沙盒执行。不自动给无 Git 项目执行 `git init`。
- 默认现状加两个候选方案，总方案数最多四个；用户可以只测现状或一个候选。不同方案不强制包含代码改动。
- 不自动安装第三方 Pi 扩展，不自动打开无限优化循环，不在基础提示词添加实验规则。

### D2. 交互入口与授权语义

- 扩展提供 `experiment` 控制工具，使用版本 1 契约；动作覆盖创建、读取、登记方案、冻结、运行、状态、取消、关联证据、比较、记录用户决定和显式清理。UI 与模型调用同一应用服务，不维护两份实验状态。
- 面板首屏是实验问题、基线和方案；运行中是进度、预算与失败；完成后是对比与证据。提供「查看原型」「看失败」「复跑」「采用」「放弃」等可发现的操作。
- 已明确要求运行且预算、数据边界明确的请求直接执行；不重复询问是否开始。用户只是讨论方案时，仅建议实验或创建草稿，不自动运行付费或有外部副作用的操作。
- 没有给预算时，先给有界的建议值并显示在实验卡：两候选、每测例一轮、单 trial 五分钟、整体三十分钟、试验执行并发一、最多六十个 trial。扩大预算需显式修改实验；这些是防失控默认值，不是统计充分性保证。
- 涉及新接收方、源码外发、凭据使用或费用的授权继续遵循项目现有边界。扩展不把安装或填写 key 当作无限调用许可。
- 性能实验允许候选原型并行制作，但默认串行、交错执行测量；不能用盲目增加并发制造不公平数据。

### D3. 领域对象与身份

| 对象 | 必要内容 |
| --- | --- |
| 实验 Experiment | 语义身份、所属项目、问题、类型、修订号、基线、方案集合、测例集、指标定义、执行策略、预算、状态 |
| 方案 Variant | 语义身份、解释的假设、代码快照／补丁或 profile、依赖与配置清单、冻结指纹 |
| 测例 Case | 输入或输入引用、可重置的初始状态、运行步骤、固定验证器、敏感性与网络需求 |
| 单次运行 Trial | 实验修订／方案／测例／重复轮次、实际 runtime 和环境、阶段计时、退出原因、指标与证据引用 |
| 报告 Report | 完整运行矩阵、比较分组、分母、差异、波动、缺失项、结论边界与原始证据索引 |
| 采纳决定 Decision | 用户来源、选择的实验修订和方案指纹、理由、交接状态；不是合并命令 |

- `experimentId`、`variantId`、`caseId` 由调用方提供短语义 slug；重复创建同一身份不覆盖旧记录。
- `trialId` 由运行时分配可读语义标识。Worker 继续使用 caller-chosen `agentId`；opaque `runId` 仅作既有运行完整性校验，不冒充新的模型可操作实验身份。
- 数据 schema 显式版本化。所有写入由实验协调器完成；可重建的汇总不成为原始记录的第二个权威源。
- 运行记录采用追加事件加原子快照；迟到事件必须匹配项目、实验修订、trial 和实际运行身份，不能回写新一轮实验。

### D4. 基线、未提交修改与重复性

- 默认基线为「当前工作内容」：提交版本加声明范围内已跟踪修改，以及用户指定或本次任务明确相关的未跟踪源码。实验卡列出纳入和排除项。既有 index、工作文件和分支均不被提交、stash、重置或改写。
- 元数据、凭据、依赖缓存、构建输出和无关未跟踪文件不自动复制。数据文件若确为测例输入，按显式输入声明纳入，而不是放开整个目录。
- 从允许内容生成不可变的快照和内容指纹。冻结时读取前后检查文件清单与内容；遇到并发改动则报告 `baseline-changed`，重取或由用户选定版本，不能发布混合时刻的基线。
- 所有方案从同一快照准备。后续实验修订生成新记录，旧 trial 继续指向旧快照。主工作区继续开发不改变正在测量的内容。
- Git 工作树属于现有管理器；运行时负责创建和登记，不手工接管其他 Worker 工作树。纯测量的临时副本可以没有可写 Git 元数据。
- 工作区及文件输入校验真实路径、符号链接和范围，不能借快照把项目外文件、宿主凭据或其他项目状态带入运行。
- 每个 trial 重置可变数据与临时 home。依赖版本、lockfile、操作系统、架构、运行器版本、可获取的模型版本和配置指纹进入证据。
- 冷／热缓存是显式不同的实验条件。不得把第一次观测称为冷启动，也不能让前一个方案的状态污染下一个方案。

### D5. 原型生成与永不自动合并

- 代码原型由实验专用 Worker 在受管理的隔离工作树生成；复用现有 `prototype` 的逻辑／UI设计方法，不把「原型不写测试」照搬为「实验无需验证」。
- 注册运行时即记录实验用途及 `mergePolicy=never`。它是权威生命周期字段，不是 prompt 提示、环境变量暗号或故意制造的失败状态。
- `mergePolicy=never` 必须覆盖成功、verify 通过、Boss 接受、重试收尾、会话工作区合并和手工合并入口。原型可正常报告生成成功，但原型树不会因此进入正式树。
- 不冒用 secretary 角色，不伪造 `failed`／`needs-user`，不以保留 dirty 文件来阻止合并。普通开发 Worker 的默认合并语义保持不变。
- Worker 只能在批准的方案范围中修改；冻结后的测例、验证器和协调器记录对它只读。越界或改变验证规则使该方案本轮无效。
- 生成完成后由协调器保存候选指纹和差异，解除运行占用，但不自动删除唯一原型。后续 trial 使用该候选的冻结副本，不能边修改边测量。
- 原型成本与正式 trial 成本分栏，不能隐藏在「方案更省」的统计外，也不能把一次性原型制作开销混入每次运行的性能。

### D6. 执行所有权与本地安全边界

- 新增实验专用执行端口，提供启动、状态与取消；由可信运行时验证冻结的执行清单与实验所有权，再接入现有运行身份、取消、超时、进度和终态记录机制。
- 该端口是本规格新增的内部集成面，不是当前 `invoke.agent` 或 `pi.events.emit` 已具有的能力。UI 的 `invoke.agent` 只进入扩展控制面，不能变成任意宿主命令执行器。
- 命令 trial 使用非 LLM 的执行驱动，不为了启动一个 benchmark 多消耗一次模型推理。代码原型和实际 Pi trial 才使用相应 Pi 进程。共用生命周期策略而非新建常驻通用 Job 服务。
- 若需要复用的生命周期逻辑目前封装在 subagent 工具内部，做最小机械提取并保留原有测试；不能通过伪造工具文本、递归启动 PipiUI 或绕过运行登记来实现调用。
- 本地受限执行适配器以 `@anthropic-ai/sandbox-runtime` 为候选实现底座，落实版本锁定、许可证检查、打包可达性和平台能力探测。未完成探测或限制未生效时返回 `sandbox-unavailable`，不自动降级为裸进程。
- 对实际原型／trial 进程树施加限制，而不只是限制某一个 bash 调用。只允许写本次工作副本和声明的临时输出；正式项目、Git 公共元数据、实验账本和固定验证器不可写。
- 限制敏感文件读取；不能依赖 srt 的默认全局可读行为。使用最小 env allowlist、独立 home 和最小可用 runtime 资源，不继承整份宿主 `.env`、auth、trust、浏览器登录态或全部 vault mounts。
- 网络默认关闭。允许模型域名、明确依赖下载或测试服务时，记录目的与白名单；不以允许 localhost 为由放开所有宿主服务。依赖安装仍是可观测阶段，保持现有代理并发上限。
- PipiUI 提供的宿主侧工具也必须执行实验用途约束，不能让受限 Worker 通过 RPC 请求主树写入、合并、打包或未授权 secret。未适配的特权工具不挂到实验 Worker。
- sandbox 是副作用边界，不是安全证明或质量判定。容器、云执行、强恶意代码对抗及新的多租户安全体系不在首版范围。
- Electron 起 Node 子进程遵循现有 `ELECTRON_RUN_AS_NODE` 与防递归生成断路器；不启动、终止或重启 Canonical App 作为实验动作。

### D7. 命令测试与固定测例契约

- 首版运行器接收结构化命令、参数、限定 cwd、输入清单、超时与产物约定。需要 shell 语法时显式声明 shell 模式，仍只在受限进程中解释。
- 一个测例的准备、被测工作负载、验证和清理为不同阶段。主要性能指标默认只包含被测工作负载，同时报告含准备及重试的总墙钟成本。
- 数值来源包括运行时单调时钟、固定验证器的结构化 JSON 及声明的项目指标文件。扩展校验名称、单位、方向、来源、有限数值和期望字段，不能从任意模型回复中抽一个数字当实测。
- 每个 trial 保留 stdout／stderr 的有界日志、退出码、信号、计时、原始指标文件及校验结果。截断有标记；摘要不能替代被截断的原文，也不能声称其完整。
- 被测进程输出和产物均为不可信数据；读取产物必须限制大小和真实路径，不能因为文件名是报告就执行其中内容。验证器运行也不得让候选代码在未受限的协调器进程内执行。
- 测例缺少确定性质量检查时允许探索性运行，但报告不能给出「质量达标」；运行前必须说明该限制。

### D8. Pi 行为评测适配器

- 使用与方案声明一致的真实 Pi runtime；记录可执行程序身份、版本、模型／thinking、工具、技能、扩展、提示词和测试任务的有效配置。未验证的宿主能力不得被默认视为可用。
- 首版优先在适配器后复用 `pi-coding-agent-eval` 的真实 Pi 会话与 profile 对比能力，固定经过验证的包版本；它不是对 PipiUI 兼容性的先验保证。
- 禁止直接依赖用户全局 PATH 上碰巧找到的 `pi`。适配层显式绑定目标 runtime；若库仅支持 PATH，用本次进程专属的 launcher 目录绑定，不修改系统 PATH 或全局安装。
- 每个 trial 使用项目内独立的实验 Pi 家，只装配声明的资源，遵守项目隔离。宿主或依赖不提供的能力报告 `capability-unavailable`，不得静默换成不同 agent 配置完成任务。
- 对纯 Pi 工具、提示、模型和扩展策略可以进行真实进程比较；依赖 Electron 主进程、原生窗口或桌面操控的方案不能用裸 Pi CLI 报告等价验收。
- 收集 provider 返回的 usage 与实际工具事件；按 trial 归属汇总，避免主会话、原型 Worker、评分器及 trial 的重复计数。缺失值为未知，不以零填补。
- 费用区分 provider 返回、价格表估算与真实账单；即使已有 ledger 字段名为 cost，也不自动称为账单实支。无可靠价格只报告 token。
- 兼容性验收先用真实 Pi 进程加 scripted provider 和固定 fixture，不能只 mock 掉 Pi 进程。真实模型实验须有预算及所需数据／凭据授权，未运行时明确记录。
- 若固定版本库不满足隔离、身份或取消契约，适配器不得报告 ready；先提供具体不兼容证据，不偷偷换 runtime 或自建另一套完整评测框架。

### D9. 公平比较与报告规则

- 冻结后不得就地修改问题、案例、评分器、候选或预算。新方案、指标或输入形成新修订，只有条件兼容的 trial 才在同一比较组中汇总。
- 默认交错、平衡方案顺序，记录 seed 与实际顺序；不承诺远端模型可完全确定复现。性能并发默认一，增加并发要声明资源分配和测量影响。
- 报告原始样本量：独立测例数、重复轮次、成功／失败／超时／取消／无效数。重复同一测例不能被写成新增独立样本。
- 质量以声明的固定验证器为首选；人工评价和 model judge 单列来源。首版不默认调用 model judge，也不让候选方案自由改评分器。
- 成功率以实际启动的 trial 为基本分母，运行失败和超时计失败；已计划但未启动的项另列。取消／基础设施无效单列并标记比较不完整，不静默删除后宣告胜出。
- 报告 paired 差值及每个测例的变化，保持单位和方向。耗时统计明确成功组与全部启动组的口径，超时不能当作完整任务耗时混入均值而不说明。
- 默认展示原始点、范围和可计算的中位数。P95、置信区间和显著性仅在采用了说明清楚的方法且样本足够时提供；首版不提供未经校准的「置信分」。
- 多指标不自动合成总分。用户可声明主要目标与不可退步约束；没有唯一胜者时展示取舍，不强制排名。
- 对比报告分三层：执行是否完整、检查是否通过、是否有证据支持实验假设。用户是否采用是独立决定。
- 正式对比必须能离线从已保存的记录重新生成，不能需要重新调用模型才能还原数值。AI 只生成有证据引用的解释；解释与机器指标分开保存。

### D10. 界面原型与浏览器证据

- UI 方案沿用 prototype 的多方案设计方法，尽量保留被讨论页面的真实结构；读写数据使用已声明夹具或 stub，不能调用生产写接口。
- 预览服务由实验生命周期登记并管理，在受限工作区启动；端口和 URL 来自本次运行，不让模型猜端口或复用来源不明的现有服务。
- 浏览器自动化仍由具有 browser 工具的主会话执行，不给普通 Worker 新增桌面权限。扩展生成固定步骤与预览定位，主会话逐步执行并将实际工具证据关联到 trial。
- 预览使用实验用途的独立浏览器上下文／分区，不复用日常网页登录态；这是首版需要补齐的窄浏览器集成，不假定当前工具已经接受 experimentId。
- 「关联证据」引用宿主实际保存的浏览器操作结果，校验实验、trial、视口和时间范围；模型粘贴的文字或用户手工上传的截图可以作补充材料，但不能冒充自动执行证据。
- 预览连接仅允许注册的本地目标，测试期间不自动对外提交数据或上传文件。模型从页面读到的内容不成为新的任务授权。
- 响应式验收同时保留桌面／手机结构观察与截图；交互记录表明在哪个视口执行。截图只是视觉证据，不能代替真实点击、状态断言或后端测试。
- 若浏览器能力未启用，可以保存／导出原型并标记视觉验证未执行；不得因此报告视觉验收通过。命令与 Pi 实验不受浏览器缺失影响。
- 取消或显式关闭预览仅终止本实验登记的服务与上下文，不影响用户其他浏览器页面或 Canonical App。

### D11. 生命周期、预算与恢复

- 实验主要状态为草稿、已冻结、运行中、已结束、已归档；trial 状态包含排队、准备、运行、验证、成功、失败、超时、取消、无效和中断。采纳决定不复用 trial 成功状态。
- 运行请求使用实验修订和请求完整性键防重复调度；重试同一次启动不创建重复收费任务。显式复跑创建新 trial，旧记录保留。
- 协调器跟踪排队及在途工作；取消同时阻止新调度并取消属于本实验的进程树。以实际终态为准，不能点击停止就先显示全部结束。
- 单 trial 超时、整体墙钟、轮数和并发上限由运行时执行。token／费用仅在可观测 usage 到达后计量；不把软预算宣传为能在计费前精确截断。预算报告包含可能的在途消耗。
- 扩展禁用不再接受新任务，并发起停止其在途实验；能力撤销后迟到事件只能收尾，不得新建任务。会话结束停止该会话的在途执行，持久实验仍可在项目面板查看。
- 宿主异常退出后的运行一律先标记待核实／中断；依据精确身份与存活证据协调清理，不按复用 PID 杀进程，不自动重跑付费 trial，不自动重启宿主。
- 正常运行需要有界进度事件；日志读取按大小和频率限制。失败消息可关闭，关闭不删除证据、不撤销已发出的取消。
- 清理只针对登记的本实验产物，必须先确认没有活跃 owner。不自动删除含唯一修改的原型分支；用户显式放弃后仍需展示并确认清理对象。报告默认保留，可独立清理大体积预览／工作副本。

### D12. 持久化、隐私与来源

- 实验设置、记录和运行状态严格归属当前项目 Pi 家的实验目录，不是跨项目共享服务。物理存储约束见补充说明。
- 原始记录、冻结清单、结果摘要与证据索引分别保存；报告引用内容指纹。跨项目不能凭一个 slug 读到另一个项目的实验。
- 默认导出仅包含去敏的清单、指标、结论和可分享证据；源码、完整轨迹及截图可能含私密内容，必须显式选择，不自动发布远端链接。
- 不把完整密钥、鉴权头或环境变量转储进结果；保留凭据引用的身份与有效配置指纹即可。错误输出同样需要去敏。
- Findings 和现有 token ledger 是可关联证据，不充当通用实验数据库；报告不能靠解析 Worker 自述 Markdown 生成实测成绩。

### D13. 用户采纳与正式实现交接

- 采用记录必须来源于明确的用户选择，引用确切实验修订、方案和证据。模型推荐、第三方日志、评分器输出不能自己产生用户采纳。
- 「采用」仅生成正式实现交接：问题、选中设计／候选指纹、可复用逻辑、需移除的 mock／临时代码、已验证内容、未验证内容和正式回归要求。
- 采纳不会把实验工作树直接解除 never-merge，也不会自动 cherry-pick、commit、部署或打包。正式实现是新的已授权开发任务，通过普通开发和验收路径完成。
- 用户自然语言明确要求「按 A 实现」时，可记录采纳并衔接既有计划执行流程，不要求再输入内部英文动作词；仍遵守未批准计划的边界。
- 若正式工作区与原基线已分叉，交接说明过期范围，正式实现需重新整合并复验；不得把旧报告当新代码验收。
- 证据不完整时仍允许用户明确选择继续投入，但交接必须保留风险，不得改写原实验为通过。

### D14. 第三方复用取舍

- `pi-autoresearch`：借鉴工具分层、测量日志和 dashboard；不原样启用其自主提交／回退／无限循环。若复用代码，保留许可与来源，但用户采纳和工作区权威仍由 PipiUI 掌握。
- `pi-coding-agent-eval`：作为 Pi 评测适配器的优先底座；契约与兼容检查见 D8，不成为命令／UI 实验的必装前提。
- `sandbox-runtime`：本地执行约束底座，见 D6；依赖代码可以按现有扩展分发方式交付，但能力不随扩展关闭后常驻启用。
- Harbor：已有 Pi 适配器，可作为后续批量容器评测后端；不在首版引入。
- 不同时接入所有评测框架，不建设适配器市场。首版接口只覆盖这三类实际运行，未来扩展通过 schema 版本演进。

## 测试决策

### T1. 主行为接缝

主接缝是实验控制应用服务的可观察行为：创建／冻结／运行／取消／比较／采纳请求，经过协调与执行适配器，返回持久状态、指标和证据。工具与 UI 共用这一个接缝。

大部分测试注入受控时钟、临时项目和执行适配器，验证外部行为与最终记录，不锁定内部函数拆分或私有数据结构。

只有主接缝无法证明的三类事实使用额外边界测试：真实文件与进程限制、真实 Pi runtime 契约、真实浏览器预览与观察。不能用一个 fake runner 证明沙盒或 Pi 集成可用。

### T2. 必须通过的功能与完整性检查

1. 扩展关闭不改变普通开发；控制工具与 UI 共用状态，错误可关闭。
2. 当前 dirty 内容被明确纳入或排除；freeze 不修改 index；并发改动使冻结失败而不是生成混合快照。
3. 路径穿越、项目外 symlink、跨项目 ID、超大／非法指标和迟到事件被拒绝。
4. 实验成功、verify 通过、人工接受或恢复收尾均不能自动／手工合并原型；普通 Worker 行为无回归。
5. 固定测例与评分器被改动使本轮无效；不伪造质量 PASS。
6. 平衡顺序、重置状态、重复轮次、单位、分母与 paired 差值可用确定性 fixture 证明。
7. 超时、失败、取消、未启动、缺失 usage 和估算费用均正确展示；没有数值的字段不是零。
8. 启动幂等、重复取消、预算达限、禁用／会话结束、恢复和精确清理不重复运行或误伤其他任务。
9. 采用仅产生带版本的交接，主树完全不变；旧基线报告不能给新实现背书。
10. 报告可由保存记录离线重建，并能定位到实际输出、验证器与候选版本。

### T3. 必须实跑的底层契约

- 沙盒：允许目录内的读写成功；向正式工作区、实验账本和敏感目录写／读失败；未允许网络失败；子进程同样受限；取消后本实验进程树终止。只断言命令包装字符串不算通过。
- Pi：使用目标真实 Pi 进程运行固定任务；runtime 身份、profile 有效配置、隔离 home、工具轨迹、结果检查和取消均可核验。scripted provider 使这组检查无需付费模型。
- 浏览器：真实启动独立预览，走相同操作步骤并核对状态；双视口截图和结构观察有实际证据；关停不影响其他页面。仅有 App demo mock 不算验收。
- 两个平台分别记录结果；某平台未实跑就标记未验证，不把 macOS 结果推广到 Linux。

### T4. 首轮产品试点与结论边界

- 使用现有检索评测的固定夹具或等价的明确任务，完成「现状／候选 → 本地测量 → 报告 → 用户采纳交接」完整路径；不为了交付实验台同时优化检索业务。
- 提供至少一个命令对比、一个真实 Pi 加 scripted provider 的 profile 对比、一个可切换界面原型。报告包含至少一个预期失败／超时样例，证明不是只展示成功。
- 首轮可以发现候选更慢或更差；实验台验收要求结果忠实，不要求某方案胜出。
- 对真实模型效果、费用和泛化收益的结论需要另行授权的真实任务实验。未运行不阻塞离线功能交付，但不得宣传已经验证真实模型收益。
- UI 验收与源码测试不等于 Canonical App 已更新。用户未要求打包／重启时止于 workspace 与浏览器验收。

### T5. 既有测试先例

优先参考现有扩展工具级测试、工作树 finalization／pendingReview、用户取消与 worker 生命周期、token ledger、BrowserPanel 和浏览器 host 测试。已有检索 eval 提供测例、结果完整性、失败分母和指标说明的先例。

每条切片必须选择自己的定向命令；普通 Electron Vitest 不覆盖全部 runtime 扩展测试。集成阶段再运行相应 workspace 检查与 runtime 定向测试，不让每个 Worker 重复整仓全套。

## 实施切片与验收标准

本仓库不创建外部 issue 或独立 ticket 文件。以下是完整分票；语义 ID 与待批准计划一致。每票包含用户可见路径和测试，不按纯数据库／后端／UI 横向拆分。除列出的 blocker 外不添加顺序依赖，共享契约由本规格统一约束。

### 1. `experiment-baseline`：创建并冻结可追溯实验

**阻塞于：** 无。

**交付：** 可选扩展入口 → 创建实验卡 → 从当前项目形成冻结基线 → 重新打开仍能查看。尚不运行任意命令。

**验收标准：**
- [ ] 工具与面板可创建、读取实验，显示问题、方案草稿、指标、预算和有效项目。
- [ ] 冻结记录提交版本、纳入的 dirty／未跟踪内容、排除项、内容指纹；主树和 index 无变化。
- [ ] 并发变更、范围越界和跨项目访问有明确错误，不发布部分基线。
- [ ] 草稿修改与冻结修订语义、持久记录、重开读取、禁用扩展和可关闭错误有自动测试。
- [ ] 为后续切片提供本规格确定的执行端口及结果类型的最小合同，不实现未使用的通用插件框架。

### 2. `sandbox-command-trial`：完成一条受限命令实验

**阻塞于：** `experiment-baseline`。

**交付：** 从实验卡运行一个命令测例，在受限环境生成真实状态、计时、日志和验证结果，并能停止。

**验收标准：**
- [ ] 新增实验执行适配器并接现有运行生命周期；命令 trial 不依赖额外 LLM，也不冒充现有公开 HostJob。
- [ ] 本地 srt 依赖经过版本／许可／平台探测，无法限制时拒绝运行而非静默裸跑。
- [ ] 权限、文件／网络限制、最小 env、固定验证器、子进程取消用真实命令测试证明。
- [ ] 超时、单次与整体预算、幂等启动、会话结束／扩展禁用、异常恢复和产物清理有终态证据。
- [ ] 结果卡区分执行成功、验证通过和未知指标；日志与指标 schema 不接受模型自报作为实测。

### 3. `isolated-prototype-variants`：制作不会自动合并的候选原型

**阻塞于：** `sandbox-command-trial`。

**交付：** 从同一基线生成代码候选 → 在实验卡查看差异与状态 → 冻结用于测量，正式树不变。

**验收标准：**
- [ ] 实验 Worker 使用受管理、受限的隔离工作区；工具与宿主 RPC 均执行用途边界。
- [ ] `mergePolicy=never` 在所有自动／手工／恢复合并路径生效，不改变普通 Worker 默认行为。
- [ ] 原型正常成功，不伪造失败／dirty／secretary 身份；保留候选差异和唯一提交。
- [ ] 超范围修改、改变测例和一边编辑一边测量均被拒绝或使修订失效。
- [ ] UI 展示候选与基线指纹；冻结后的 trial 从候选副本开始，而不是读取活动工作树。

### 4. `paired-command-report`：多方案公平对比与数值报告

**阻塞于：** `isolated-prototype-variants`。

**交付：** 相同测例运行现状和候选，得到可重建的对比报告、失败案例和有口径的性能数字。

**验收标准：**
- [ ] 运行矩阵、平衡顺序、重复轮次、重置和默认单并发均实际执行并留痕。
- [ ] 同条件分组、paired 差值、独立测例数、失败／超时／取消分母正确；不可比组不混算。
- [ ] 数值显示来源、单位、统计方法和缺失项，不输出未经校准的综合分或置信分。
- [ ] 报告支持查看原始证据、失败样例和显式复跑；新轮次不覆盖旧记录。
- [ ] 用确定性快／慢／错误／超时 fixture 验证报告，离线重建不调用模型。

### 5. `pi-profile-evaluation`：目标 Pi 的真实进程评测

**阻塞于：** `sandbox-command-trial`。

**交付：** 用户选择 Pi profiles，在固定任务上运行实际目标 Pi，报告配置、任务检查和可用 usage。

**验收标准：**
- [ ] 适配固定版本的 pi-coding-agent-eval；目标 Pi 显式绑定，不受系统同名 `pi` 污染。
- [ ] 测例、工具／扩展／技能／提示、模型与 thinking 有有效配置证据；不支持的宿主能力明确报告。
- [ ] 每 trial 使用独立项目内 Pi 家与最小凭据，不复制信任，不扩大原数据外发授权。
- [ ] 真实 Pi + scripted provider 的多 profile 用例通过，并覆盖取消、缺字段和配置不一致。
- [ ] usage 按 trial 正确归属，成本来源有区分；输出同一 Trial／Report 契约供比较面板消费。
- [ ] 无真实模型授权时不发付费请求，报告明确哪些效果尚未测试。

### 6. `browser-prototype-evidence`：独立预览与交互验收

**阻塞于：** `isolated-prototype-variants`。

**交付：** 用户打开并切换 UI 原型，主会话在内置浏览器执行检查，实验记录包含真实交互和双视口证据。

**验收标准：**
- [ ] 预览服务、URL和浏览器上下文绑定本实验，不复用生产登录态或未知端口。
- [ ] 普通 Worker 不获得桌面权限；主会话 browser 实际操作结果与 trial 关联。
- [ ] 正常／空／错误状态按测例验证，桌面／手机结构观察和截图齐全，视觉意见与数值分开。
- [ ] 缺 browser 时显示未验证；取消只关本实验预览，不关闭其他页面或宿主。
- [ ] 工具／host 契约测试与实际浏览器路径均有证据，mock 页面不替代真实预览。

### 7. `experiment-adoption`：由用户采纳并交接正式实现

**阻塞于：** `paired-command-report`。

**交付：** 用户看报告后选择方案，得到有版本和风险说明的正式实现交接；可以继续试验或放弃。

**验收标准：**
- [ ] 采纳只认用户来源且绑定实验修订与方案指纹；推荐文字和工具输出不能冒充用户决定。
- [ ] 交接包含验证证据、已知失败、未测事项、可复用部分及应去除的 mock／试验壳。
- [ ] 采用不会合并、解除 never-merge、提交或打包；主树保持不变。
- [ ] 基线过期和证据不足不被改写为通过；继续试验生成新修订，旧报告仍可查。
- [ ] 放弃／清理等待活跃 owner 结束，只处理明确登记且用户允许清理的本实验对象。

### 8. `experiment-pilot-acceptance`：用真实项目场景验收完整实验台

**阻塞于：** `paired-command-report`、`pi-profile-evaluation`、`browser-prototype-evidence`、`experiment-adoption`。

**交付：** 可复现的命令、Pi 和 UI 三类试点，以及从创建到用户采纳交接的完整证据；不夹带被测业务优化。

**验收标准：**
- [ ] 用现有检索类夹具做现状／候选命令对比，报告忠实呈现收益或退化，不预设赢家。
- [ ] 真实目标 Pi 的 scripted profile 对比、可切换 UI 原型及至少一个预期失败／超时样例走通。
- [ ] 冻结／停止／重开／报告重建／采纳交接串联验收，正式项目及其他实验保持不变。
- [ ] 相关 workspace 与 runtime 定向检查通过；实际浏览器验收有桌面／手机证据。
- [ ] 用户说明展示自然语言入口、预算、数据边界、依赖缺失和未验证平台／模型；不要求先配置云账号。
- [ ] 发布记录区分功能通过、实际实验结果和未执行项；未获请求不打包、不重启 Canonical App。

## 范围之外

- 所有开发强制原型、自动无限优化、自主挑胜者并合并、自动部署。
- 通用云 Job 平台、跨项目共享数据集／凭据、排行榜、评测器市场、多租户执行服务。
- 首版接入 Harbor、E2B、Daytona、Inspect AI、promptfoo 等全部后端。
- 宣称 worktree 本身提供安全沙盒，或把 srt 宣传成能证明任意恶意代码绝对安全。
- 用裸 Pi／Linux 容器替代 Electron 原生能力验收、自动桌面操作权限扩张。
- 用 LLM 自述、单次测量或主观审美制造客观数值结论。
- 借试点同时改进检索、文档生成或其他被测业务；这些需要独立开发目标。
- 修改锁定基础提示词、迁移全局 Pi 配置、复制项目 trust、整理无关 dirty 工作。
