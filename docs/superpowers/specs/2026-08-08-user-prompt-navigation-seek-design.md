# 用户输入导航线与远古消息定向跳转

## Problem Statement

会话主界面需要在左上侧提供一条用户输入导航线：每个节点对应一次完整用户输入，帮助用户把握会话结构并一键跳到任意用户消息。

当前生产路径以翻转 SwiftUI 滚动视图挂载局部窗口，默认可向旧端扩张；pin 会清理已加载历史。导航节点必须来自全量会话，而可见内容只是局部挂载，因此“节点可点”与“目标已挂载”是两回事。若为跳到远古消息而挂载目标到最新的全部区间，长会话会一次挂上海量行，引发卡顿与内存膨胀。

同时，流式输出、自动置底、历史分页、用户滚动、切会话与连续点击会争用滚动与窗口；异步跳转任务也可能在会话已切换后迟到生效。动态高度还会使首次滚到目标后位置漂移。v1 必须在保留现有生产渲染器的前提下，用有界 seek 窗口完成定向跳转，并在返回最新后恢复原有 live 语义。

## Solution

产品形态：主界面左上侧用户输入导航线。节点覆盖全量用户输入，与当前挂载窗口解耦；hover 展示纯文本摘要；点击发起跳转；当前关联节点持续高亮。导航数据始终来自完整会话索引，不依赖目标是否已在视口中。

运行时引入与 live / 单向历史并列的 seek 视口：点击导航后先退出 pin 与自动置底，再在目标附近挂载**配置化有界窗口**，禁止为远古跳转把 target 到 latest 的中间内容全部挂上。滚动由单一串行 Jump Coordinator 拥有：按 session identity + request generation 丢弃迟到任务；跳转完成后做**有限且可取消的布局稳定校正**。用户主动滚动、新点击、切会话或返回最新均取消在途协调。seek 与 history pager / live streaming 不得争夺滚动所有权；返回最新恢复原 live 分页、流式与自动置底语义。

数据侧由会话维护增量、稳定 ID 的用户输入索引，供导航线与跳转解析共用。v1 保留现有生产 SwiftUI 渲染器并叠加有界 seek，不把 Table / 真虚拟化切为默认。

## User Stories

1. 作为用户，我能在主界面左上侧看到用户输入导航线，节点顺序与会话中用户输入一致。
2. 作为用户，即使目标消息尚未挂载，我仍能看到并点击对应用户输入节点。
3. 作为用户，hover 节点时能看到该条用户输入的纯文本摘要，而非富文本或完整气泡。
4. 作为用户，点击节点后会话会滚到对应的用户消息附近，便于阅读上下文。
5. 作为用户，当前视口所关联的用户输入节点会保持高亮，与普通及仅 hover 状态可区分。
6. 作为用户，从最新区域点到很早的用户输入时，界面仍保持可用，不会为中间全部历史一次性铺开。
7. 作为用户，跳转过程中若我再点另一个节点，应以最后一次点击为准，旧跳转不得抢滚。
8. 作为用户，跳转后若我主动滚动浏览，系统应停止未完成的跳转校正，把滚动交还给我。
9. 作为用户，我可以从 seek 浏览返回最新消息，并重新获得原来的 live 追新与自动置底体验。
10. 作为用户，切换到另一会话后，上一会话未完成的跳转不得影响新会话视口。
11. 作为用户，在 live 流式输出时点击历史用户输入，应先离开自动置底，再落到目标附近。
12. 作为用户，导航线本身滚动浏览节点时不应强制加载或挂载对应消息窗口。
13. 作为用户，摘要应反映该条用户输入的可读正文大意；内容更新后摘要不应长期陈旧。
14. 作为用户，在 seek 中阅读远古上下文时，新到达的 live 流式内容不得强行夺走我的滚动位置。
15. 作为用户，连续快速点击多个节点时，最终稳定落点应对应我点的最后一个节点。

## Implementation Decisions

### 导航数据与索引

- ChatSession（或等价会话权威源）维护用户输入的增量稳定 ID 索引：有序、可按消息身份解析、transcript 追加/替换时增量更新而非全量重建为主路径。
- 导航线只消费该索引与摘要投影，不订阅“当前挂载行集合”作为节点存亡条件。
- 摘要为纯文本规范化结果：去 Markdown 渲染、控长截断、按消息 ID 缓存；内容变更或会话级替换时失效对应项。hover 只读缓存/投影，不扫全量 transcript、不挂消息视图。

### 视口模式与窗口

- 明确区分至少：`liveLatest`（默认 live）、单向历史扩张、`seek`（定向有界窗口）。
- 三者 v1 共用现有生产 SwiftUI 滚动 + eager 栈式挂载；差异在窗口切片来源、允许的扩张方向、以及谁拥有滚动。
- seek：以目标附近为中心挂载**配置化有界窗口**，在 transcript 边界自然收缩；允许有界平移换窗，禁止“目标→最新”整段挂载，也禁止借 history 单向 pager 无限扩张完成远古跳转。
- 进入 seek 必须先退出 pin 与自动置底类 live 追新。
- 返回最新：拆除 seek 切片，恢复 live 窗口与原 live 语义（分页入口、流式追加、自动置底规则与 pin 既有语义一致）。

### Jump Coordinator（单一串行）

- 全局（或每 UI 宿主）仅一条跳转协调流水线，串行执行；新请求取代未完成请求。
- 每个请求绑定 session identity + 单调 request generation；回调/异步续步必须校验二者，失败则整段 no-op。
- 标准顺序：取消旧协调 → 校验会话仍当前 → 退出 pin/自动置底 → 切换/确认 seek 并挂载目标附近有界窗口 → 滚动使目标可见 → **有限且可取消的布局稳定校正**（动态高度收敛）→ 更新“当前导航节点”。
- 取消源（立即放弃校正与后续滚动手势）：用户主动滚动、新的导航点击、切换会话、用户选择返回最新、会话销毁/宿主释放。
- 协调器是 seek 期间滚动所有权的唯一写入方；history pager 与 live streaming 在 seek 下不得竞争 scroll position（流式数据可照常入会话，但不得驱动 seek 视口置底或改写窗口所有权）。

### 当前节点与导航 UI

- “当前节点”由视口关联策略更新（跳转完成态与用户在已挂载窗口内浏览时的稳定关联）；不得要求仅因高亮就挂载全历史。
- 普通 / hover / 当前样式可区分；当前 + hover 时保持当前主身份并叠加 hover 反馈。
- 导航线节点视图自身可懒构建；与消息挂载窗口生命周期分离。

### 滚动所有权总表

| 模式/场景 | 窗口谁改 | 滚动位置谁写 |
|-----------|----------|--------------|
| live 自动置底 | live 窗口策略 | live 置底逻辑 |
| 单向历史分页 | history pager | pager/用户手势约定的既有行为 |
| seek 跳转中 | seek 窗口策略 + Coordinator | 仅 Coordinator |
| seek 用户已接管 | seek 可有界平移（若产品允许） | 用户手势；Coordinator 已取消 |
| 返回最新 | 恢复 live | 恢复 live 语义 |

## Testing Decisions

采用一个最高层黑盒 seam，外加两个纯逻辑 seam；不把性能测试写进用户故事。

### 黑盒 seam：导航跳转

从导航节点发起跳转，断言：

- 目标用户消息最终可见（或稳定落在其有界上下文中且目标在窗口内）。
- 最终高亮/当前节点为用户最后一次有效点击对应节点。
- 挂载行数保持有界，不出现 target→latest 全量挂载。
- 注入延迟/过期回调时，迟到任务不得抢滚或改写已切换会话的视口。

覆盖交互：连续点击、跳转中用户手动滚动、跳转中返回最新、跳转中切会话、live 流式进行中发起 seek。既有 pin、history pager、会话隔离测试作为先例与回归锚点（扩展其隔离与所有权约定，不另起平行体系）。

### 纯逻辑 seam A：索引一致性

给定 transcript 追加、中段变更、整体替换等序列，用户输入稳定 ID 索引的顺序、成员与可解析性与权威 transcript 一致；增量更新后无重复/漏节点/悬挂 ID。

### 纯逻辑 seam B：viewport / jump reducer

纯状态归约：模式转换（live ↔ 历史 ↔ seek ↔ 返回最新）、generation 作废、取消源、滚动所有权标志。断言非法转移不发生，seek 下 pager/streaming 不能取得滚动所有权，迟到 generation 的 effect 被丢弃。

### 性能

固定合成长会话（可含复杂气泡高度）为基线夹具。同一夹具上测量：seek 路径挂载行数量、主线程卡顿相关指标、峰值内存；与“错误地整段挂载”或改动前基线对照，验证有界窗口带来的相对改善与无回退。不设定无测量支撑的绝对百分比 SLO；窗口与校正预算保持配置化，便于调参复测。

## Out of Scope

- 不将默认生产渲染器切换为 Table / NSTableView 真虚拟化。
- 不做消息磁盘分页或变更现有消息持久化模型。
- hover 摘要不渲染 Markdown/富文本，不挂完整消息视图。
- 不借本功能重做会话同步、多端协作或导航线以外的信息架构。
- 不为远古跳转提供“挂载目标至最新的全部中间消息”的兼容模式。

## Further Notes

长期若配置化有界 SwiftUI seek 经 profiling 仍无法满足长会话流畅度，再推进 Table / NSTableView 真虚拟化：全量轻量 entry、稳定 row 定位、增量更新与高度缓存。该路径仅作为后续选项，不阻塞本 spec 的 v1 交付，也不得在本阶段切为默认渲染器。
