## 问题陈述（Problem Statement）

内置浏览器已经支持结构化 DOM 观察、区域展开、分页、语义 locator、批处理和流程复用。但默认观察按页面结构给出区域摘要，复杂页面上与当前小目标相关的控件可能不在最先展示的内容中。主模型因此需要反复观察、展开、阅读，才找到可以直接操作的目标。

现有 Jev 优化扩展仅为代码候选提供可选云评分，没有接入浏览器。机械地给每次点击或观察增加请求，可能增加延迟和费用；仅重排已经截断的结果，也找不回未展示的候选。

用户需要的是更短的任务完成时间且不降低成功率，而非单独减少输出 token。没有 TypeSafe key 或不愿外发页面内容的用户，必须保留完整的本地操作路径。

## 解决方案（Solution）

在现有 `browser` 工具的 `observe` 动作上增加可选 `intent`：由主模型描述当前一步要找的目标。浏览器在原有可见范围和明确过滤条件内，先形成有界、脱敏的候选集合，在最终展示截断之前进行确定性本地排序；符合条件且用户另外允许浏览器内容外发时，再请求一次 Jev 评分。

工具仍返回真实页面的结构化观察、区域信息和可操作引用，不执行任何自动点击。没有意图的旧调用保持原行为。用户无需更换主模型，也不需要使用另一个 Jev 工具。

两条路径是：

1. 本地路径：观察与候选准备 → 本地排序 → 发布正常观察；一次宿主调用即可完成。
2. 可选云路径：准备候选快照 → 一次有界 Jev 评分 → 校验并发布该快照的观察。服务不可用或评分无效时采用同一候选池的本地顺序，不重新扫描来伪装回退。

这是目标相关信息选择，不是动作代理、页面摘要生成器或通用优化平台。

## 用户故事（User Stories）

1. 作为浏览器使用者，我希望复杂页面优先展示与当前目标相关的控件，以便减少重复展开和阅读。
2. 作为主模型，我希望在原有 `observe` 调用中说明当前小目标，以便不为生成检索意图额外发起一次模型调用。
3. 作为没有 Jev 的用户，我希望目标相关观察仍能本地工作，以便不增加账号、网络或费用依赖。
4. 作为旧工具调用方，我希望不传 `intent` 时得到原有观察行为，以便无需迁移已有脚本和流程。
5. 作为已经知道唯一 locator 的调用方，我希望直接操作目标，以便不为明确动作支付额外评分成本。
6. 作为有 TypeSafe key 的用户，我希望另行决定是否允许浏览器控件描述外发，以便代码检索授权不会自动扩展到网页数据。
7. 作为用户，我希望清楚知道会外发哪些内容，以便判断该项目是否适合启用浏览器优化。
8. 作为用户，我希望关闭浏览器外发后立即停止新的相关上传，以便无需重启宿主才能撤销授权。
9. 作为代码检索用户，我希望单独关闭浏览器优化不影响已有代码重排，以便两个数据范围相互独立。
10. 作为主模型，我希望评分只改变候选次序，不生成控件、locator 或脚本，以便引用仍对应真实页面。
11. 作为主模型，我希望窗口、弹窗、页面限制和截断信息始终可见，以便优化不隐藏影响下一步操作的事实。
12. 作为用户，我希望页面变化或迟到回答不会产生混用快照的引用，以便避免错点。
13. 作为用户，我希望服务故障时继续看到本地观察结果，以便可选优化不阻塞基本操作。
14. 作为取消任务的用户，我希望取消后不再上传或发布迟到结果，以便停止操作也停止相关工作。
15. 作为使用桌面/移动视口的开发者，我希望两个视口的引用保持隔离，以便不能串用元素 token。
16. 作为主模型，我希望得知还有未展示或未扫描的内容，并可返回普通观察，以便排名靠后不被解释为不存在。
17. 作为评测者，我希望分别比较旧观察、本地目标筛选、同候选加 Jev，以便不把本地优化的收益算给云模型。
18. 作为维护者，我希望同时看到成功率、完整耗时、模型轮次和费用，以便只在真实收益成立时宣传提速。

## 实现决策（Implementation Decisions）

### D1. 工具入口与兼容性

- 不新增模型可见工具或动作名。`intent` 是 `browser.observe` 的可选非空字符串，trim 后最多 512 个 Unicode 字符；单动作和 `actions[]` 内的 observe 都支持。
- `intent` 表达当前一个查找目标，不从会话历史自动推断，也不另外调用 LLM 生成。浏览器工具自身指导说明何时使用，不能修改锁定基础系统提示词。
- 非 observe 动作携带 `intent` 返回明确参数错误，不静默忽略。navigate、click、input、wait 成功后的自动观察不继承先前 intent，不偷偷增加云请求。
- 省略 `intent` 时保留现有区域摘要、分页、定位、输出预算和错误语义；不得让所有普通观察经过新的云流程。
- `scope`、`region`、`role`、`name` 仍是本地硬约束，先过滤后排序。不能因为目标相关性越过 scope 或放宽明确名称/角色条件。
- 首版不为目标排序新增可持久化分页协议：`intent` 与非空 `cursor` 同传报参数错误。需要继续穷举时，省略 intent，使用原有区域/过滤/分页接口。文档和工具帮助必须明确这一点。
- `target=active/desktop/mobile` 支持可选云评分；`target=both` 支持两份独立的本地目标观察，但首版跳过云评分，标记 `multi-target-local`。两个视口不得共享快照、候选 ID 映射或评分结果。
- 已有唯一 locator、snapshot token、明确批次或可复用 `browser_flow` 时继续直接执行，不为本特性重新解释确定动作。

### D2. 有界候选与确定性本地基线

- 在最终区域预览和元素列表截断之前，复用 DOM 控制器的遍历、可见性、可操作性和同源边界形成候选。不扩大到跨域 iframe、关闭的 shadow root、canvas 或其他页面。
- 每次单视口准备最多保留 256 个合格候选，候选描述序列化合计最多 64 KiB；超过预算停止保留新候选并明确 `incomplete` 及原因。结构/限制信息扫描不随候选预算提前停止，避免漏掉后置弹窗；重定位身份仍按过滤前的同名次序保持一致。沿用既有 DOM 遍历边界，不承诺整个页面采集具有新的硬实时上界。
- 本地排序只使用已有可公开的 accessible name/label、role 和区域名称；不新增 embedding、网络或第二次 LLM 调用。规范化空白和大小写后，依次比较完整目标文本命中、名称词项覆盖、区域词项覆盖；拉丁词项按词边界切分，连续中文按双字片段匹配。角色/name 硬过滤仍优先于评分。并列保留原 DOM 次序，无区分度保留原序。
- 本地排序前 64 个形成评价窗口。B/C 对照必须使用完全相同的这个窗口和内容；窗口之外的候选不冒充已获 Jev 评价。
- 有 intent 的观察直接展示最多 12 个目标候选和对应区域摘要，仍受原有观察信封上限约束。保留真实的区域计数、页面/弹窗结构信息、焦点信息（原来提供时）、限制及预算截断标记；不能让 Jev 排名决定是否展示这些事实。
- 不以相关性分数阈值宣布元素无关或不存在。输出记录收集数、评价窗口数、展示数和未完整覆盖的原因，省略 intent 后仍可使用原有观察路径。
- 没有 Jev、没有 key、未获浏览器外发授权时，本地目标观察不是错误，也不触发等待云端的超时。

### D3. 快照准备与发布

- DOM 元素引用和指纹始终留在页面/宿主控制层。Jev 和扩展间协议只获得候选描述、局部 ID 和必要的内部关联信息，不持有 DOM 对象或驱动动作的权限。
- 本地路径在一次原有宿主调用内完成准备、排序与发布；不得为无 Jev 用户固定增加 prepare/finalize 两次 loopback 往返。
- 云路径使用两个内部阶段：准备时保留有界待发布候选快照及其本地顺序；评分返回后，仅用合法候选 ID 和次序要求宿主发布。内部阶段不作为新的模型可见动作，不接受任意 JS、CSS 或服务端新造元素。
- 待发布快照按会话、tab、viewport 隔离；每个视口只保留一个，最多存活 5 秒。导航、销毁、另一轮观察或结构/交互相关 DOM 变更使其失效；过期项惰性清除，关闭视图/会话时全部清除。不得持久化候选快照。
- 发布时校验当前文档/视口身份、待发布快照版本和所选元素的现有可见性/指纹。失效返回可重试的 `browser_observation_changed`，不发布旧 token，不自动重试 Jev。
- 在最终选择完成后，由原有发布路径分配 snapshot/element 引用；不能由云服务生成或改写 token/index。既有点击时 stale、遮挡、可操作性及同页重定位校验照常执行。
- 评分服务故障或未授权时使用准备阶段保存的本地顺序；页面本身已变化则不能把旧本地结果当作安全回退。
- prepare/finalize 的宿主时间计入端到端评测；不能用新增内部 RPC 隐藏真实优化成本。

### D4. 窄浏览器评分服务

- 复用 Jev 扩展的官方端点、凭据、HTTP 错误分类、响应校验、取消及生命周期实现，不复用绑定源码路径/行号的候选类型，也不修改代码检索现有协议含义。
- 浏览器消费者与 Jev 提供者通过进程内、版本化的 `pipiui.browser-reranker.discover.v1`、`provide.v1`、`withdraw.v1` 握手；加载顺序无关，未发现提供者立即本地，不等待发现。
- 提供者身份仍为 `jev-optimizer`。offer 的职责仅为浏览器评分 availability/rerank，不建设通用服务市场，不静态互引两个扩展。
- 输入是 intent、至多 64 个脱敏候选、项目授权上下文和取消信号。每候选包含局部 ID、role、name/label、region 名称；不上传 DOM 路径、locator、element token、snapshot ID、URL、标题、表单值或整页 HTML。
- 最终 HTTP 请求体上限 64 KiB，单候选描述上限 768 UTF-8 字节。持有 key 的提供者先对完整描述脱敏，再按字段安全截短、缩小稳定的评价窗口；消费者的进程内转发不能先切断秘密匹配边界。不能截断 JSON 或原始 intent。前级已有截断时，可识别的已知 key 边界前缀应保守跳过上传；这不构成任意未知秘密的清除保证。若预算不能容纳有效请求，跳过云评分。未进入实际云评价窗口的候选仍保留在本地尾部，不计作零分或无关；B/C 对照记录实际评价窗口，不改变两组初始候选集合。
- 每次合格 observe 最多一次评分请求，所有候选同批提交，等待预算 1500ms；无自动重试、无跨调用评分缓存、无逐候选串行请求。
- 仅使用 Score，0=无关，1=相关背景，2=有助于定位，3=直接对应当前查找目标。候选是数据，不是指令。首版不引入 Choice 自动执行。
- 校验完整候选 ID 集合、重复 JSON key/回答、类型、有限分数及范围；非法响应整体回退，不拼接部分评分。平分保留本地顺序，全部无区分度保持本地结果。
- 不向主模型呈现内部准备结果，不把内部候选文本记作模型已读；仅最终观察进入正常工具结果。

### D5. 浏览器内容外发授权与撤销

- Jev 设置增加项目级 `ext.jev-optimizer.browserEnabled`，默认 false、缺字段按 false；不迁移为 true，不因已有 TypeSafe key 或已启用代码重排而自动开启。
- 设置展示名为“允许浏览器候选云端评分”，明确说明当前目标和脱敏控件/区域描述会发送给 TypeSafe、可能收费，且不会发送截图或整个页面。此字段是新增数据范围授权，不是第二个冗余的代码检索开关。
- 不新增 key 输入、账户流程、每次观察确认或独立弹窗。需要重新加载会话才能挂载扩展/新 key 时复用已有说明，不要求重启 Canonical App。
- 宿主是授权事实来源。运行时状态增加浏览器授权状态及独立撤销代际；旧状态没有这些字段时拒绝浏览器上传，但不能因此破坏原有代码重排。
- 单独切换浏览器授权不轮换代码检索正在使用的凭据代际；浏览器请求捕获本次授权代际，发送前及等待期间检查，关停或代际变化取消请求并丢弃迟到评分。关闭整个扩展、清除/替换 key、session shutdown 沿用原有撤销机制。
- 同一已挂载、凭据有效的会话应能看到浏览器授权变更，无需建设通用扩展热加载。未挂载的会话依原生命周期生效，不假称可以热挂载。
- 复用浏览器已有脱敏规则；敏感输入节点不进入云候选，不能通过拼接 label/value 绕过排除。intent 同样经过已知敏感值脱敏；脱敏容量不足时不发请求。
- 控件名称本身可能含业务数据。不得宣传“脱敏保证没有隐私”；项目授权是额外云接收方的明确选择。API key 仅用于鉴权头，日志不记录 intent、候选、请求/响应原文或秘密。
- 不修改 browser capability、跨项目隔离或 Worker 权限；启用评分不为原本没有浏览器能力的 Worker 授权。

### D6. 失败、取消和可观察性

| 情况 | 行为 |
| --- | --- |
| 无 intent | 完全沿用普通观察，不探测/调用浏览器云评分 |
| 无提供者、未启用、无 key、浏览器授权为 false | 立即使用本地目标观察，上传次数为零 |
| 候选不足两个、候选描述完全重复、预算不足 | 本地顺序；稳定的 skipped reason |
| 双视口目标观察 | 两份独立本地观察；`multi-target-local`；零云请求 |
| 超时、401/429/5xx、断网、非法评分、flat scores | 同候选池本地顺序；不再请求云服务 |
| 关闭浏览器授权或撤销 provider | 取消在途云请求；若快照仍有效则发布本地结果 |
| 用户取消 | 取消等待，不再发起 finalize 或任何后续宿主调用；现有批次停止语义不变 |
| 页面/候选快照变化或过期 | 返回可重试的 `browser_observation_changed`，不发布旧引用 |

- 最终工具 details 增加独立的观察优化元数据：`local/applied/skipped/fallback`、稳定 reason、候选/评价/展示数、各阶段耗时、可得的 API usage。无 intent 的老调用不强加这些字段。
- 元数据区分本地过滤、Jev 评分和页面变更；云失败不能伪装成 DOM 观察失败，页面变更也不能记作评分成功。
- 文本只显示必要的简短说明，不把全部候选、评分表或重复快照塞回上下文，继续遵守现有单观察与批结果预算。追加元数据和宿主标签后再次复查每个视口的 20,000 UTF-16 JSON 信封；超限明确返回 `browser_observation_budget`，保留有界测量但不返回该视口的引用，不继续批次尾部。合法双视口合计不被错误压为单视口预算。批次保留单视口或两份嵌套的优化元数据。
- 批次预算包括内部评分阶段；失败、取消后不执行后续动作。已有浏览器流程不保存 intent 内部快照/临时引用，也不为了优化修改流程持久化协议。

## 测试决策（Testing Decisions）

### T1. 主要接缝

主要验收接缝是一次注册后的 `browser` 工具调用：输入参数、能力桥请求、网络调用数、最终观察/错误及后续使用引用操作的结果。复用现有浏览器扩展的工具捕获/能力桥测试和 JSDOM 页内脚本执行模式，为当前 DOM 控制器补建针对性夹具，注入可选评分器及可控时钟。当前没有可直接复用的完整 controller 单测套件，不能把 legacy 单文件工具测试当作现行扩展的行为证据。

只保留两类必要的下层补测：真实 DOM 控制器快照/脱敏/发布行为；Jev HTTP 与宿主授权撤销。它们覆盖工具 mock 无法证明的边界，不为各私有函数建立一套平行框架。

好测试验证可观察行为：同一目标是否展示、引用能否指向真实元素、关闭授权是否零上传、页面变化是否拒绝旧结果。不能只断言调用某个内部函数，也不能用另一个模型的评分充当唯一真值。

### T2. 功能验收矩阵

1. 旧 observe 的普通/过滤/分页/双视口及批次回归不变；其他动作的执行路径不新增评分。
2. intent 参数长度、空白、错误动作、cursor 组合均有明确契约测试。
3. 无 Jev 的目标观察端到端可用，且宿主调用次数不因云协议增加。
4. 大页面目标位于普通区域预览之外时，在候选预算内可进入目标观察；超过采集预算如实报告不完整。
5. scope/region/role/name 硬过滤不被任何分数越过；中英文目标、同名控件、本地无匹配和并列顺序有金标。
6. 正常观察限制、结构信息、截断信息不被评分删除；省略 intent 可恢复普通分页。
7. 有效云评分改变顺序但不新增候选；所有展示 token 能由原有点击路径解析；双视口不能串用。
8. 无授权/缺 key/未挂载/关闭扩展/双视口/预算不足均零上传；旧代码重排授权不自动允许网页上传。
9. 云请求不含表单值、URL、标题、DOM 路径、snapshot/token、原始 HTML 或已知秘密；脱敏失败不上传。
10. 超时、HTTP 错误、非法/缺失/重复标签、重复 JSON key、越界分数和平分，保留本地结果且不重试。
11. 准备后导航、DOM 变更、销毁、被新观察替换、过期、取消及 provider 撤销，不得发布串用引用或继续批次尾部。
12. 浏览器授权 false→true→false 的代际竞态会丢弃旧评分，单独切换不使现有代码重排失效。
13. 单次请求 64 候选/64 KiB、候选描述/采集预算、单观察和批输出预算有边界测试。
14. 没有 key 也能运行全部确定性契约测试；不得把模拟云评分通过写成真实 Jev 效果。

### T3. 小实验与归因

准备至少 12 个可公开/合成 DOM 金标案例：区域预览外目标、多个区域的同名控件、中英文表达、语义与词面不一致、弹窗、表单敏感内容、同源 iframe、范围过滤、页面变更、无匹配、超预算、双视口。金标由夹具预先标注目标和必须保留的信息，不由评分器产生。

分开跑两类实验：

- 观察级对照：12 个案例，每组至少重复 3 次。A=现有无 intent 观察；B=确定性本地 intent；C=B 的同一候选窗口加真实 Jev。记录目标 Recall@12、必要信息覆盖、输出 token 估计、采集/桥接/评分/发布耗时、上传次数和回退比例。
- 完整任务探索实验：从金标中固定 4 个可独立判定完成的多步任务，每组重复 3 次，共 36 个 A/B/C 任务运行。固定主模型、thinking、任务提示、起始页面、工具预算和完成判据，按轮次轮换组序。记录成功/失败全部运行，不仅统计成功子集；工具动作序列不能预先替主模型决定。

B/C 的语义输入和候选窗口保持一致；A 只缺少新 intent 能力，任务目标相同。数据集不得按看到 C 的结果后挑选或重新标注。记录主模型调用数、工具调用数、误操作/重试、整任务 P50/P95、模型实际 usage、Jev usage 和总费用；无实际账单时费用标记未核实，不能伪造实价。

真实云实验只发送生成的合成夹具内容及合成 intent；不得读取真实登录页面、用户浏览历史、工作区正文或表单数据来凑样本。使用已获授权的凭据/浏览器外发设置，不为测试自动购买额度或启用真实项目页面外发。

若开发测试宿主无法加载本次源码、没有可用 key 或外发授权，确定性部分照常交付，真实部分必须记录“未执行”及原因，不能用 mocked 结果补齐。已有工具/宿主可运行环境与打包 App 是不同证据；本计划不自动打包或重启。

### T4. 如何决定是否值得保留

- 功能可用的门槛：T2 通过，金标中的安全/范围/引用要求无回归；云关闭时本地功能仍完整。
- 排序门槛：C 相对 B 的目标 Recall@12 和必要信息覆盖不下降，失败案例逐条展示。
- 提速的实验目标：C 相对 B 的完整任务中位耗时至少改善 20%，成功次数不降低，P95 不高于 B 的 110%。这是预先设定的探索性门槛，不是保证；只有 4 个独立完整任务，重复不等于新增独立样本，不能宣称统计普适性。
- A→B 与 B→C 的收益分开报告。C 没有胜出时，应明确“未证明 Jev 净提速”，不暗中调低标准或扩大到动作 Choice 追求好看的结果。
- 总费用没有下降不能宣称“更省钱”；任何结果都不自动把浏览器外发设置改为默认开启。

## 纵向切片与分票

以下保留已批准切片及验收定义，勾选框不是实时状态表；执行状态以结构化计划及实现报告为准。每票是一条可独立验证的纵向路径，不按 schema/host/UI 横向拆票。共同架构已由 D1–D6 确定，不交由各 Worker 自行选择协议。

### 1. `intent-observe-local` — 本地目标相关观察完整路径

**阻塞于：** 无。

**交付：** 主模型通过现有 browser.observe 传入 intent，即可在没有 Jev/key 的情况下得到目标相关控件与原有可用引用；普通观察保持原样。

**验收：**

- [ ] 工具 schema/help、参数校验、桥接、DOM 有界候选、本地排序、最终观察贯通。
- [ ] 本地一次宿主调用；按 D1 支持硬过滤/双视口并明确 cursor 限制。
- [ ] 实现 D3 的内部候选准备/发布能力，本地仍同次调用完成；用受控测试验证跨阶段变化不发布旧引用，为可选云消费者提供既定接缝。
- [ ] 命中普通预览之外的金标目标；展示上限、结构保留、预算不完整与普通分页退路均可验证。
- [ ] 工具/DOM/宿主相关回归通过；不改 Jev 服务、不新增云请求。

### 2. `browser-eval-baseline` — 可复现夹具与旧观察基线

**阻塞于：** 无；可与第 1 票并行。

**交付：** 不依赖新功能即可运行的 12 个合成金标案例、4 个完整任务定义，以及 A 组旧观察的基线记录入口。

**验收：**

- [ ] 每个案例有固定初始状态、目标真值、必要信息和完成判据；可重复重置。
- [ ] A 组离线观察/引用检查可在现有测试宿主运行；数据缺失或失败计入报告。
- [ ] 记录格式区分工具级与完整任务级、估计 token 与实际 usage、真实运行与模拟评分。
- [ ] B/C 接入使用同一夹具/判据；本票不得引入 Jev 调用或改浏览器产品代码。

### 3. `optional-browser-jev` — 独立授权的可选浏览器云评分

**阻塞于：** `intent-observe-local`。

**交付：** 已挂载 Jev、凭据有效且另外允许浏览器外发时，合格的单视口目标观察自动采用至多一次云评分；关闭/失败时仍返回本地路径。

**验收：**

- [ ] 设置说明、默认关闭、宿主授权状态、浏览器独立撤销代际、进程内提供者发现与 browser 消费全链路贯通。
- [ ] 复用现有 HTTP/凭据设施，新增窄候选契约；不更改代码检索协议或默认行为。
- [ ] 按 D3 准备/评分/发布；严格 ID 校验，不创造控件；取消、页面变更、旧请求迟到有回归。
- [ ] 按 D4/D5 限制载荷与等待，敏感候选不上传；无授权零请求，故障无重试。
- [ ] 单独撤销浏览器权限不破坏代码重排；双视口固定本地；details 能解释实际采用的路径。

### 4. `browser-jev-evaluation` — 集成验证、A/B/C 对照与结论

**阻塞于：** `browser-eval-baseline`、`optional-browser-jev`。

**交付：** 同一集成树上的契约验证和有界实验报告，明确“实现可用”与“端到端提速已证明/未证明/未执行”。

**验收：**

- [ ] 运行 T2 相关集成回归，在第 2 票夹具上跑 A/B 和模拟 C 契约；不以模拟结果评价 Jev 质量。
- [ ] 有已授权凭据/合成数据条件时按 T3 执行真实 C 与完整任务对照；条件缺失则明确记录未执行及影响，不改为上传真实页面。
- [ ] 报告样本数、固定模型/预算、组序、成功和失败、P50/P95、轮次、费用/usage、回退及原始有界记录。
- [ ] 按 T4 给出归因和结论；性能未胜出不扩范围、不改默认授权、不宣称已提速。
- [ ] 全差异代码审查与实际验证是两条独立证据；按项目流程收尾，不把打包/重启当测试步骤。

- 不对测试接缝、票粒度另开审批轮；它们随本规格一次批准。批准前仅交付文档和计划，不启动实施。
