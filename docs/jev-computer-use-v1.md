# Jev AX 桌面操作循环规格 v1

- 日期：2026-09-22。
- 状态：待批准；本文件是设计，不代表功能已实现、已打包或已证明提速。
- 实施计划 ID：`jev-computer-use-v1`。
- 决策来源：用户要求参考 PipiCOC 的 Jev agent loop 与公开 Jev computer use 案例，让 Jev 智能查找 AX 控件、选择动作并连续执行，而不是只给 AX 排序。
- 本轮交付：规格与完整实施切片；业务代码在用户批准实施计划后开始。不创建 issue tracker、标签或独立票文件。

## 问题陈述（Problem Statement）

现有桌面操作由主模型逐步阅读 AX 和截图，再调用工具。对打开菜单、定位输入框、选择选项、输入已知文字等任务，大部分步骤只需要选择动作和目标，不需要生成自然语言解释，却仍支付主模型往返与图像上下文成本。

当前宿主请求的 AX 上限为 2000 个元素、深度 25；扩展按角色筛选后只展示前 48 个元素。这个顺序不保证目标在首屏，缺失的控件还可能需要展开、滚动或打开菜单后才出现。只在这 48 个元素上评分解决不了动态查找，也不能减少每步都由主模型决策的问题。

用户需要的是更短、更可靠的完整桌面任务路径：主模型给出小目标及已知输入值，Jev 在受控循环中查找控件、选择动作，既有宿主执行并反馈；只在结束或需要接管时返回主模型。没有 Jev 或不允许桌面内容外发时，现有直接操作必须继续可用。

## 解决方案（Solution）

在现有 `computer` 工具中增加显式、独立的 `action=goal`，启动一个有界的 AX 优先桌面循环。先由现有 `open_application` 绑定目标应用与窗口；循环不自行切换到其他应用。

流程为：读取固定目标的实际 AX 状态 → 本地构造有界控件索引与可执行操作 → Jev 选择查看索引、展开、滚动或具体操作 → 宿主绑定并校验参数 → 通过现有 Cua Driver 执行 → 重新观察并继续。

这里的“索引”是当前 AX 快照的本地结构化目录，不是向量库，也不是把整棵树持久化到 Jev。找到了明确控件便直接给出可执行候选，不强制经过多层目录。Jev 不生成解释文字、任意坐标、脚本或自由 JSON；宿主拥有实际参数，Jev 只选择已提供的选项。

首版使用 AX，不新增 OCR、截图视觉模型、另一套桌面驱动或后台桌面 agent。既有驱动观察仍包含截图；循环中间结果不反复进入主会话的图像上下文，但不能据此声称底层不再截图。

## 用户故事（User Stories）

1. 作为用户，我希望一次交代明确的小目标，让系统连续完成若干桌面操作，而不是每次点击都等待主模型。
2. 作为用户，我希望系统能够先查找控件再操作，而不是要求目标必须出现在最先返回的 AX 列表中。
3. 作为用户，我希望系统在需要时展开菜单、切换标签或滚动，使尚未出现的目标变得可操作。
4. 作为用户，我希望已提供的搜索词、路径和文件名被原样输入，不再让另一个模型重新生成。
5. 作为用户，我希望不需要新文字的任务只做事，不在每一步生成解释性回复。
6. 作为用户，我希望明确知道桌面目标和控件描述会发给 Jev，并可独立关闭这一行为。
7. 作为用户，我希望沿用已有 Jev 凭据，不增加第二份 key 或账户流程。
8. 作为没有 Jev 的用户，我希望普通 `computer` 与 `open_application` 完全可用。
9. 作为用户，我希望循环只控制已选定的应用，不因为其他窗口抢到前台而误操作。
10. 作为用户，我希望同一应用的合法弹窗被现有宿主识别，而不是继续点击被遮挡的父窗口。
11. 作为用户，我希望取消后不再产生新的云请求或动作，并如实看到已执行的部分。
12. 作为用户，我希望在找不到、无进展、执行结果不确定时得到可接管状态，而不是无限重试。
13. 作为用户，我希望需要创作内容或处理敏感输入时交回主模型，而不是猜测参数。
14. 作为主模型，我希望以目标、具名输入值和预算启动循环，不必逐步提供 AX token。
15. 作为主模型，我希望收到结构化动作记录、停止原因及最终观察，而不是另一份长篇推理。
16. 作为主模型，我希望 `DONE` 只表示控制器请求结束，不被当作任务成功的证据。
17. 作为维护者，我希望云端只能选择当前提供的候选，不能制造 token 或越过宿主的窗口与快照校验。
18. 作为维护者，我希望遗漏、截断和未搜索范围显式保留，不能把未看到解释成不存在。
19. 作为维护者，我希望确定性点击和现有批处理不增加 Jev 请求或改变语义。
20. 作为评测者，我希望分别测量 AX/截图、Jev 决策、驱动执行、主模型往返和完整任务耗时，不混淆收益来源。
21. 作为评测者，我希望失败任务也计入成功率、耗时和误操作统计，不只挑选成功演示。

## 实现决策（Implementation Decisions）

### D1. 显式入口和兼容性

- 保留 `open_application` 的绑定入口，以及现有 `computer` 单动作和 `actions[]` 合同。
- 新增独立 `computer(action=goal)`，不允许嵌入 `actions[]`，也不与单次坐标、键盘或元素动作参数混用。普通动作不会自动升级为 Jev 控制。
- `goal` 为明确的小目标，trim 后 1–512 个 Unicode 字符。可选 `inputs` 是具名文字输入列表，每项有语义 `id`、简短 `label` 和原始 `value`；ID 必须唯一。最多 16 项，单值最多 8 KiB、全部原值合计最多 32 KiB；超限明确拒绝，不截断输入值。
- `max_steps` 默认 12、范围 1–30；`timeoutSecs` 默认 30、范围 1–60。一次 Choice 轮次消耗一步，包括索引导航；观察、网络等待和动作执行均计入总时间，任何子过程不能续预算。
- `goal` 需要当前会话已有有效目标、桌面能力授权和桌面执行开关。没有目标时返回要求先调用 `open_application` 的结构化交接，不猜测应用。
- 首版仅主会话可用，不向 subagent 增授桌面能力，不启动独立持久桌面 worker，不增加第二个工具入口。

### D2. 模块职责与集成接缝

- 桌面工具扩展拥有目标循环、局部索引、候选操作构造、输入绑定及结构化结果。
- 桌面宿主继续拥有会话身份、能力授权、目标绑定、串行执行、快照校验、坐标映射与驱动生命周期。增加的内部循环调用仍走同一能力桥，不建立旁路执行器。
- Jev 扩展提供窄的桌面决策服务，复用现有凭据、HTTP、取消、错误分类和响应校验基础设施，但不冒用浏览器候选类型、CDP 租约或浏览器外发授权。
- 桌面消费者与提供者使用版本化的进程内 `pipiui.computer-choice.discover.v1`、`provide.v1`、`withdraw.v1`。没有提供者时立即返回可接管结果，不等待发现或阻塞普通工具。
- 不照搬 PipiCOC 的游戏语义、证据覆盖问题或只读并行执行代码；只复用“动态可执行选项 → 决策 → 执行 → 新观察”的模式。

### D3. 快照局部索引与主动发现

- 候选来自当前目标的真实 AX 观察，使用扩展展示前的完整有界元素集合，而不是已经截成 48 个的工具文本。底层采集上限保持现状，不声称覆盖整棵 AX 树。
- 本地保存原 token、元素索引、角色、名称、实际存在的状态与动作、层级信息和窗口归属。只有驱动实际提供的字段才进入判断，不推断不存在的父子关系或值读取能力。
- 有可信层级时按容器/区域组织；没有层级时使用稳定的扁平分组与分页，不引入额外模型生成分组摘要。保留弹窗、当前焦点、来源截断和遗漏计数。
- 先用本地确定性匹配把目标相关控件与分组提到前面，再构造至多 48 个操作选项，其中预留必要的“查看下一组/页”选项。匹配使用已有目标词与公开名称，不增加 embedding 或一轮主模型调用；无区分度保留原顺序。
- 每次允许选择：查看某组或下一页、刷新观察、点击真实可操作控件、通过真实 disclosure/menu/tab 控件展开内容、滚动、等待、结束、交接。分组/分页只改变本地候选视图，不伪装为 UI 状态变化。
- 滚动、展开和菜单动作仍调用已有执行器；不假设驱动存在尚未核实的任意子树查询 RPC。底层已截断且缺少可行探索操作时报告覆盖不完整并交接。
- 每次外部状态变化使旧快照的候选映射失效。索引仅保存在本次调用内，不持久化、不跨会话/项目/窗口复用。已访问记录同时考虑语义控件与状态，既防止原地循环，也不禁止状态变化后重新访问同一控件。
- 候选越多不代表必须先翻页：当前视图已有可执行目标就直接选择。普通已知 token 的外层工具调用完全不经过该索引。

### D4. Jev 决策合同与参数绑定

- 每轮最多一次 Jev 请求；不先 Score 全树再 Choice，也不为构造候选额外调用主模型。
- 输入是任务目标、允许外发的当前 AX 语义、精简动作历史、可执行选项及输入值的 ID/label。内部 token、snapshot ID、pid、原始坐标、截图和完整 AX 原包不出现在云载荷中。
- 首版使用一组带语义描述的操作候选：每个可执行候选对应宿主已绑定的完整动作；其他候选只能推进本地发现或参数绑定，不直接产生 UI 写操作，避免组合出不匹配的“动作类型＋目标”。
- 有多个输入值时，可以先选择一个具名输入 ID，再为它选择可写控件；单值可直接绑定。这个本地绑定选择也消耗一次决策预算，后续候选显式带上当前输入的 ID/label。不要把全部字段与全部值的笛卡尔积塞进单次请求，也不能用词面不匹配静默排除可能的绑定。实际执行前再次检查输入 ID、字段类型和快照。
- 响应只允许已提供候选 ID，含明确的结束与交接选项。严格校验必需答案、类型、候选集合和有限概率；未知/缺失/无效答案不能执行。置信度不充当授权或完成证明，不以任意固定阈值承诺安全。
- 云请求序列化上限 64 KiB。先完整脱敏，再安全裁剪描述或缩小候选窗口，保留分页/遗漏信息；不能截断任务、JSON 或输入原值来凑预算。无法构造有效请求则交接。
- 原始输入值留在宿主，Jev 只选择输入绑定。输入字段含敏感/secure 标志时不提供输入操作；未提供内容、需要创作、身份验证或不能明确判断目标字段时交接。
- 输入通过现有工具支持的聚焦、键盘选择/输入路径完成，不发明 AX set-value 能力。动作子序列必须先满足既有批处理合同；若快照或上下文变化，立即停止并重新规划，不能继续旧子序列。
- Jev 不是自由字符串生成器。首版不在循环内调用写作模型；主模型可先生成普通内容并作为具名输入交给下一次调用。

### D5. 执行、目标归属与进度控制

- 一轮最多执行一个选中操作；操作可包含已知且受现有宿主验证的确定性子序列。桌面写动作不并行、不投机执行，不重排用户的 `actions[]`。
- 每次写动作之前再次校验能力、项目、目标与快照；实际执行继续使用原 token/index 与既有 Cua Driver。Jev 不生成坐标、菜单路径、shell、AppleScript 或可执行代码。
- 同一应用的弹窗/窗口跟随由现有宿主的权威机制决定，Jev 不能另选窗口绕过它。应用切换、无权威归属的窗口变化或目标被用户重新绑定时停止并交接。
- 循环占用目标时，复用现有桌面串行化规则；并发手工调用必须明确报告忙或使本轮失效，不能交错使用同一快照。不得为等待 Jev 长时间占有底层 driver RPC 锁；下一动作前验证会话目标版本。
- 新 UI 状态到来后重建候选；物理动作之后重新观察。只做本地索引导航时可以沿用同一有效快照，但下一次实际执行仍需校验其新鲜度。
- 连续两次实际动作未产生可观察语义变化且没有发现新候选时返回 `no_progress`。指纹不包含随机截图 ID、快照编号或时钟；合法分页前进不是无进展。没有足够可观测字段时标记验证不足，不能编造状态变化。
- `stale_snapshot` 至多触发两次有预算的重观察与重新选择，不自动重放旧动作。`mutation_outcome_unknown` 立即交接；恢复观察也不能被当作允许重放。
- 明显发送、购买、支付、删除、安装、权限提升或认证等操作不由首版快循环提交，交回主模型按原始授权处理；不增加每次普通点击的确认弹窗，也不宣传能识别所有高后果操作。

### D6. 配置、外发与撤销

- 沿用当前项目 Jev 扩展已有凭据入口和存储，不建立另一份 `TYPESAFE_API_KEY`、通用 vault 或桌面 key。凭据具体实现以当前代码为准，不借本功能迁移存储。
- 新增项目设置 `ext.jev-optimizer.computerEnabled`，缺省 false。它只授权向 Jev 发送桌面目标和控件描述，不替代宿主的 `computerUseEnabled`、桌面能力 grant 或系统 Accessibility 权限。
- 设置说明明确额外云接收方、可能费用及数据范围。开启浏览器云决策或代码检索不自动开启桌面外发；不因已有 key 默认勾选。
- 宿主运行时状态增加独立桌面外发状态与撤销代际。开关关闭、凭据清除/替换、提供者撤回或会话取消时，取消在途请求并丢弃迟到答案；发送前、答案返回后和动作之前检查状态。
- 单独关闭桌面外发不取消浏览器或代码检索；缺失桌面状态字段时拒绝桌面云请求，但不破坏其他消费者。
- AX 文字按不可信界面数据处理，不能覆盖任务或授权。排除 secure 控件值，原始字段值与具名输入值不上传；对目标与描述进行已有秘密值脱敏。控件名本身仍可能含业务数据，不能宣传脱敏保证没有隐私风险。
- 不增加每步授权仪式；已启用和已挂载时沿用可用状态。未挂载扩展的会话不假称支持热挂载，沿用现有生效说明，不要求重启 PipiUI。

### D7. 停止、返回与证据

- 结果为有界结构化数据：状态/原因、决策次数、实际动作数、简短动作轨迹、已完成部分、是否需重新观察、最终观察、各阶段耗时与可得 usage。轨迹不包含长解释、秘密或原始输入值。
- 状态至少区分 `needs_verification`、`handoff`、`budget_exhausted`、`aborted`、`unavailable`、`invalid_request`；原因区分无目标、无提供者/未授权、缺输入、覆盖不完整、无进展、过期、执行结果不确定及服务错误。
- Jev 选择结束后返回 `needs_verification`、`verified:false`。宿主对可观察的局部效果做核对，但不把局部点击成功或模型自报等同于整体任务完成；主模型在最终观察上独立验收。
- 缺 key/关闭外发/未挂载时不发云请求、不执行动作，返回交接信息；普通直接操作保持可用。Jev 失败后不偷偷换主模型继续自动操作，也不自动重启另一个 goal。
- 取消尽力中止在途请求和未开始的动作；已提交给 OS 的一次合法动作无法承诺撤销。保留已执行记录，不自动回滚 UI。
- 中间 AX/截图留在本地控制路径，只把必要的进度元数据与末次有效观察返回主会话，沿用现有截图存储/显示机制。异常结束时不得把之前窗口的图片当成当前目标。
- 没有使用新无图 driver API，因此实测需单列截图采集成本；“不把每步截图发给主模型”与“没有截图”是两件事。

## 测试决策（Testing Decisions）

### T1. 主要验收接缝

以一次注册后的 `computer(action=goal)` 调用作为主要接缝：输入目标、具名值和预算，使用可控 Jev 服务与假 Cua Driver，贯通真实扩展、能力桥、宿主目标绑定和执行校验，检查云请求、驱动调用、观察更新和最终结果。不能只测候选构造函数或绕过宿主直调执行闭包。

只保留两类必要的下层测试：Jev HTTP/授权代际与取消；驱动回包到本地候选的映射、分页和有界性。既有直接工具、host pin/stale/batch 测试作为回归。现有主测试脚本排除部分 runtime 扩展目录，实施时必须显式接入扩展测试，不能用一个未覆盖它们的绿灯宣称通过。

好的测试预先定义目标控件、实际执行对象和最终 AX 状态；不以另一个模型的评分或 Jev 的 `DONE` 为真值。秘密测试使用合成值，外发授权测试证明“零请求”，不只看状态字段。

### T2. 必测行为矩阵

1. 不传 goal 时旧单动作、批处理、截图、坐标映射和 `open_application` 无额外云请求、行为不变。
2. goal 参数、输入 ID/值预算、独立调用限制与上下文授权校验失败时零动作；没有 target 不自动启动应用。
3. 当前可见目标一次选择即可操作；处于原前 48 个之外的目标能经本地索引找到，引用仍指向真实控件。
4. 无层级、同名不同区域、中英文名称和未知角色有确定性降级；不存在的信息不能变成候选事实。
5. 分页、查看分组、打开菜单、展开 disclosure、切换标签及滚动后目标出现，候选正确刷新；未扫描范围不被宣称不存在。
6. 输入值原样送达本地执行器；多个输入 ID 不串用；缺值、secure 控件、需要生成新内容均交接；Jev 请求不包含原始输入值。
7. 类型/目标不匹配、未知候选、非法概率、缺失答案和超预算响应不执行；当前快照外的 ID 不可复用。
8. 同应用合法弹窗按宿主跟随；切到别的应用、旧窗口、用户重新 pin、并发操作均不误点。
9. snapshot 更新、迟到响应、超时、取消、撤销及 key 变更不能执行旧决策；未知结果的 mutation 不被重放。
10. 分页前进不误报无进展；连续真实 no-op 有界停止；同名按钮状态变化后可以再次成为合理候选。
11. 每轮至多一次云请求，所有子调用共享总 deadline；预算耗尽有完整部分进度，不能续预算。
12. 无 provider/key/桌面授权时零云请求、零 goal 动作；桌面撤销不影响 browser/context 的既有授权。
13. secure 值、已知秘密、输入值、token、pid、坐标与截图不进入云载荷或诊断；超大描述与 Unicode 边界不破坏脱敏。
14. 高后果候选交接而非执行；普通点击不产生新的确认仪式。
15. `DONE` 固定返回未验证状态；点击成功但目标未完成的夹具不能被计为任务成功。
16. 最终观察属于当前目标；中间截图不反复注入主会话；错误/交接结果可继续使用原工具恢复。

### T3. 对照评测与完成口径

先建立至少 12 个合成 AX 场景，覆盖可见点击、列表后部目标、分组/分页、同名控件、菜单展开、滚动后出现、已知文字输入、模态变化、过期、无进展、敏感控件与 AX 覆盖不足。每个场景有预先确定的完成谓词及禁止动作。

从中固定 4 类可在受控应用重现的完整任务：设置页导航与选项切换、菜单查找、输入已知搜索词、滚动查找目标。每组每任务至少 3 次，轮换运行顺序，不在看到结果后更换任务或金标。

- A：现有主模型逐步使用 `computer`，工具、模型及 thinking 固定。
- B：新局部索引/绑定/执行循环配确定性决策替身，仅检验基础设施和成本，不当作智能基线，也不计为真实 Jev 结果。
- C：同一新路径使用真实 Jev；主模型只下发目标并做最终验收。

记录成功/失败全部运行：完整耗时 P50/P95、主模型调用数和实际 usage、Jev 请求数/usage、AX 与截图时间、索引时间、网络决策时间、执行时间、误操作、重试、交接及中间截图进入主模型的次数。未拿到真实账单时费用标记未核实，不用估算冒充计费。

功能门槛是 T2 全部通过、旧工具回归通过。提速的探索性目标是 C 对 A 中位耗时至少下降 20%，成功次数不降低、禁止动作零发生且 P95 不高于 A 的 110%；少量重复不构成普适统计证明。未达标如实报告“未证明净提速”，不改默认开关、不事后降低门槛。

真实云评测仅在已有凭据和明确的桌面外发授权下发送合成内容，不自动开启设置、购买额度或操作真实业务账号。实际 OS 评测由主会话在专用测试应用中执行；运行 App、系统权限或打包需遵守各自授权。没有真实环境时仍完成确定性验证，并明确标记真实评测未执行及原因，不把 mock 结果代替实机。

## 非目标（Out of Scope）

- 不是全自主跨应用 agent；不让 Jev 自己选任意应用、窗口或后台桌面。
- 不新增 OCR、视觉 grounding、图像理解、任意坐标生成、拖拽或驱动尚未支持的动作。
- 不新增 AX 无图采集 RPC，不重写、替换或 fork Cua Driver，不引入 Swift/SwiftUI 产品目标。
- 不做持久 AX 搜索引擎、向量库、跨任务缓存、学习用户工作流或通用 agent 平台。
- 不在循环里创作文本、猜凭据、自动处理认证，亦不移植 PipiCOC 游戏运行时。
- 不更改 browser goal/Score、代码检索、现有批处理或 Worker 权限。
- 不修改锁定基础提示词；工具说明只放在相关能力层。
- 不默认开启桌面外发；不把打包、安装、重启 PipiUI 当作源码验证步骤。

### 纵向切片与阻塞关系

以下每个切片覆盖自己的入口、逻辑、执行/返回与测试，不按 UI/后端/模型拆成水平层。第一批是最小闭环和独立基线；后续控制循环能力按已落定的接口顺序扩展，避免并行修改同一状态机。完成证据以实施计划和测试结果为准，不能把本列表当成已完成记录。

#### 1. `ax-goal-core` — 可见 AX 目标的完整 Jev 操作闭环

**阻塞于：** 无。

交付显式 goal 入口、项目桌面外发设置与撤销、窄桌面 Choice 服务、当前固定窗口的真实候选绑定、可见控件点击/刷新/等待/结束、预算与结构化结果。保留供后续切片扩展的候选及输入合同，不提前实现全部发现策略。

验收：一个可见目标经过注册工具、Jev 替身、真实宿主桥和假 driver 完成点击并返回新观察；无目标/无授权/无 key 零执行；取消、撤销、错误答案、旧 token 不执行；DONE 未验证；普通工具回归不变。不得仅返回“计划点击”冒充闭环。

#### 2. `ax-eval-baseline` — 固定 AX 夹具与原路径基线

**阻塞于：** 无，可与第 1 片并行。

交付 T3 的合成场景、禁止动作、4 类完整任务定义与统一指标记录入口，建立 A 组基线入口和 B 组确定性回放能力。只建立可重复证据，不向产品代码注入预设答案，不开启真实云授权。

验收：原路径能够执行夹具并独立判定成功；失败与缺失数据进入记录；可区分替身/真实服务、估算/实际 usage；准备好同一数据集供后续 C 组使用。

#### 3. `ax-adaptive-discovery` — 从有界 AX 索引主动找到目标

**阻塞于：** `ax-goal-core`。

交付截断前候选构造、分组/扁平分页、本地相关性优先、菜单/控件展开和滚动发现、新快照候选刷新、覆盖标记与无进展停止。动作执行仍归宿主，不新增驱动 RPC 或 OCR。

验收：目标在原前 48 个之外、展开后才出现、滚动后才出现三类任务走通；无层级可退化；分页不是 no-op；旧目标不可误用；覆盖不足不会报不存在；两次真实无进展停止。

#### 4. `ax-bound-inputs` — 给定参数的连续桌面任务与交接

**阻塞于：** `ax-adaptive-discovery`；需要其动态定位及同一状态机的刷新/重规划语义。

交付具名输入值的本地绑定、聚焦/输入/受支持快捷键等确定性操作、敏感/缺输入/需生成内容的交接，以及多步任务的完整轨迹与最后观察。主模型不参与中间填参，Jev 不自由生成字符串。

验收：从定位输入框到原样输入已知文字并触发普通搜索的完整任务可运行；多个值不串用、不外发；上下文变化中断旧子序列；未知 mutation 结果不重放；高后果动作交接；整体成功仍需独立判定。

#### 5. `ax-integration-evaluation` — 全链路回归与真实收益结论

**阻塞于：** `ax-eval-baseline`、`ax-bound-inputs`。

交付同一集成树上的 T2 全矩阵、旧工具回归、最终整体审查，以及 A/B/C 对照报告。真实验证按已有权限/环境执行；不能运行的部分标为未执行并说明原因。

验收：注册工具到宿主的证据贯通；runtime 扩展测试确实被执行；没有步骤、错误或失败样本被静默丢弃；报告分别给出“实现可用”和“真实 Jev 净提速已证明/未证明/未执行”。无需、也不自动打包或重启 PipiUI。
